Version 2.0.0 — Major Release

Multi-session development · March 2026

✨ New Features
  • NEW
    Unified Login System (Single Entry Point) — Replaced separate Researcher and Reviewer login pages with one unified login interface at /login/. Role-based automatic redirection: Researchers go to /researcher-dashboard/, Reviewers to /reviewer-dashboard/. Already-logged-in users are redirected immediately without seeing the form. templates/frontend/unified-login.php · includes/api/class-researcher-handler.php · includes/core/class-upgrader.php
  • NEW
    Reviewer Email OTP Verification Gate — Reviewer logins now require a 3-step email OTP flow: (1) enter registered email → (2) enter 6-digit code sent via wp_mail() → (3) enter password. OTP is cryptographically generated with random_int(), stored as a hashed WordPress transient with 5-minute TTL, consumed on first use. A short-lived verification token is issued to the login form and verified server-side before wp_signon() proceeds. Full rate-limiting: 3 OTP sends / 5 verify attempts per IP per 10 minutes. includes/api/class-researcher-handler.php (send_reviewer_otp, verify_reviewer_otp)
  • NEW
    Submission Form — Step-by-Step Wizard — Converted the 10-section submission form from a scroll-spy tab layout (all steps visible at once) to a true one-step-at-a-time wizard. Includes: animated progress bar, Prev/Next/Submit navigation, per-step validation with inline error messages, step indicator pills with active/done states, and a "Save draft" link accessible on every step. templates/frontend/submission-form.php
  • NEW
    Real-Time Article Status Synchronisation — Researcher Dashboard now polls for status changes every 30 seconds on the Submissions tab via a new lightweight AJAX endpoint (eiu_rp_get_article_statuses). When a reviewer updates a status, a fixed-position toast notification slides in — "Article status updated — click to refresh" — without any delay. Each article row carries data-article-id and data-status HTML attributes for comparison. templates/frontend/researcher-dashboard.php · includes/api/class-researcher-handler.php
  • NEW
    Submission Form Access Wall — Non-researchers/non-reviewers visiting the submission page now see a branded access-denied wall instead of a plain error string. Includes: lock icon, "What you need" requirement list, Contact Admin (mailto) button, Apply as Researcher button, and Sign In link — all linking to the correct unified login page. includes/core/class-plugin.php (render_submission_form)
  • NEW
    Published Article Edit Lock — Researchers can no longer edit articles with "published" status. Attempting to navigate to the resubmit URL for a published article shows a clear "Article is Published — Editing Locked" screen with a lock icon and administrator contact guidance. The "Revise & Resubmit" button is replaced by a "Read-only" badge on published articles in the submissions list. templates/frontend/researcher-dashboard.php
🐛 Bug Fixes
  • FIX
    Critical: "Network Error" on OTP Send button — Root cause: send_reviewer_otp() queried wp_eiu_reviewers WHERE ... AND is_deleted = 0 but the is_deleted column did not exist on the eiu_reviewers table (only on eiu_reviews). This caused a MySQL "Unknown column" error, which printed into the output buffer before the JSON response, making fetch().then(r => r.json()) throw a SyntaxError, triggering the catch handler with "Network error". includes/api/class-researcher-handler.php · includes/core/class-upgrader.php (migrate_1_6) · includes/core/class-activator.php
  • FIX
    Submission form step 4 blocked by non-existent field validation — stepValidation[4] referenced author_org but no such input field exists in the Author Details step HTML. This caused step 4 validation to always fail silently, blocking users from advancing. The field was removed from the validation array. templates/frontend/submission-form.php
  • FIX
    PHP 7.4 incompatibility in article status polling endpoint — get_article_statuses() used the PHP 8.1 spread operator (...$args) in a $wpdb->prepare() call. This caused a fatal error on PHP 7.4 servers. Replaced with call_user_func_array([$wpdb, 'prepare'], ...) for full PHP 7.4+ compatibility. includes/api/class-researcher-handler.php
  • FIX
    Stale teal/pill/desc CSS conflicting with red reviewer identity — The unified login template retained several orphaned CSS rules from an earlier design iteration: .ul-role-pill, .ul-role-desc, .ul-role-pill-reviewer (teal), and .role-reviewer step-indicator overrides. These conflicted with the correct red (#990000) reviewer visual identity. All stale rules removed. templates/frontend/unified-login.php
  • FIX
    Stale role-reviewer JS setting teal colours on reviewer login — An init IIFE in the unified login template added the role-reviewer CSS class to the wrapper element when the reviewer tab was pre-selected. This class applied teal (#0f766e) step-indicator colours, overriding the correct EIU Red. JS block removed. templates/frontend/unified-login.php
  • FIX
    Wizard nav bar missing mobile responsive styles — The .eiu-sf-wizard-nav, .eiu-sf-nav-btn, and progress bar elements were not covered by the existing @media(max-width:640px) rule. On mobile the nav bar overflowed and buttons were oversized. Mobile CSS added for all new wizard elements. templates/frontend/submission-form.php
  • FIX
    Redundant polling fallback JS using fragile CSS class regex — The real-time polling code contained a fallback that attempted to populate data-status attributes by running a regex against badge CSS class names (/st-([a-z_]+)/). Since data-article-id and data-status are now set directly in the PHP template, this fallback was redundant and error-prone. Removed. templates/frontend/researcher-dashboard.php
  • FIX
    Reviewer dashboard inline login form bypassed unified login system — The reviewer dashboard template had its own inline POST-based login form (eiu_reviewer_login nonce) that was entirely separate from the unified login flow. This dual-login system caused confusion and bypassed the OTP gate. The inline form was removed; unauthenticated users are now redirected to the unified login page with a redirect_to parameter. templates/frontend/reviewer-dashboard.php
⚡ Enhancements
  • ENHANCE
    Abstract WYSIWYG editor upgraded — Added formatselect (paragraph/heading dropdown), block_formats (H2, H3, H4), blockquote, full image embed support, and image_advtab. Editor height increased to 10 rows. Content style updated to render headings at correct sizes inside the editor preview. templates/frontend/submission-form.php
  • ENHANCE
    Login page role distinction — colour-coded cards — The two role tabs on the unified login now use full card-style buttons with individual icon badges and two-line labels ("Researcher / Submit & track articles" vs "Reviewer / Review assigned articles"). Researcher tab: EIU Blue (#1a4988). Reviewer tab: EIU Red (#990000). A colour-coded banner beneath the tabs updates instantly on switch to confirm the active role. templates/frontend/unified-login.php
  • ENHANCE
    Personalised navigation bar user menu — When a Researcher or Reviewer is logged in, their name, role badge, and avatar appear in the WordPress nav menu. A dropdown provides links to Dashboard, My Profile, and Sign Out. Completely theme-agnostic: four-step injection strategy covers any WordPress theme. Login menu items are automatically hidden when logged in (server-side filter + client-side JS). includes/core/class-plugin.php · assets/js/nav-user-menu.js · assets/css/nav-user-menu.css
  • ENHANCE
    Dashboard Sign Out visibility improvement — Both Researcher and Reviewer dashboard sidebars now feature a high-contrast dark navy (#0a1628) footer with white text and a full-width red hover state (#990000). Previously the Sign Out link was a muted grey barely visible at the bottom of the sidebar. templates/frontend/researcher-dashboard.php · templates/frontend/reviewer-dashboard.php
  • ENHANCE
    Cross-role access protection on both dashboards — Reviewers visiting the Researcher Dashboard are redirected to their own dashboard, and vice versa. Prevents role confusion and accidental cross-access. Administrators bypass both guards. templates/frontend/researcher-dashboard.php · templates/frontend/reviewer-dashboard.php
  • ENHANCE
    Database: is_deleted column added to eiu_reviewers — The column was present in eiu_reviews but missing from eiu_reviewers. Added via migrate_1_6() using idempotent ALTER TABLE … ADD COLUMN (checks with DESCRIBE first). Also added to the CREATE TABLE definition in the activator for fresh installs. Schema version bumped to 1.6. includes/core/class-upgrader.php · includes/core/class-activator.php
  • ENHANCE
    Database table auto-bootstrap on ZIP upload installs — When the plugin is installed by uploading a ZIP file, WordPress does not fire register_activation_hook. The upgrader's maybe_upgrade() now checks whether the primary table (wp_eiu_articles) exists on every plugins_loaded call. If missing, it runs Activator::bootstrap_tables() and schedules deferred page creation. No data loss possible — all DDL uses CREATE TABLE IF NOT EXISTS. includes/core/class-upgrader.php · includes/core/class-activator.php
  • ENHANCE
    Login menu items hidden for logged-in users — A wp_nav_menu_items PHP filter (priority 20) adds class="eiu-rp-login-hidden" to any <li> whose href matches known login URLs or whose text matches common login phrases. Client-side JS also hides matching items (including Elementor nav widgets) before the user widget is injected. display:none !important in CSS ensures immediate hiding. includes/core/class-plugin.php · assets/js/nav-user-menu.js · assets/css/nav-user-menu.css
  • ENHANCE
    Unified login page auto-created for existing installs — migrate_1_5() creates a WordPress page at slug /login/ with shortcode [eiu_unified_login] for all existing installations. Deferred to init hook so wp_insert_post() runs when $wp_rewrite is available. If a page with slug login already exists, the option is updated to point to it instead. includes/core/class-upgrader.php
  • ENHANCE
    Researcher dashboard auth guard uses unified login — Changed from redirecting to the old /researcher/ login page to the new unified /login/ page, passing a redirect_to parameter so the user returns to their dashboard after login. templates/frontend/researcher-dashboard.php
  • ENHANCE
    [eiu_researcher_login] shortcode backward compatibility — The old shortcode now delegates to the unified login template. All existing pages using [eiu_researcher_login] continue to work without any content changes required. includes/core/class-plugin.php
  • ENHANCE
    Researcher dashboard published articles show read-only badge — Published articles in the Submissions tab now display a green "Published — Editing Locked" label and a grey "Read-only" badge with a lock icon. The "Revise & Resubmit" button is suppressed for published articles. templates/frontend/researcher-dashboard.php
🔐 Security
  • SECURITY
    Output buffer guards on all AJAX handlers — ob_start() at entry and ob_end_clean() before every wp_send_json_*() call in send_reviewer_otp(), verify_reviewer_otp(), and unified_login(). Prevents any stray PHP output (notices, warnings, debug messages) from corrupting the JSON response. includes/api/class-researcher-handler.php
  • SECURITY
    Email enumeration protection on OTP send — send_reviewer_otp() always returns an identical success response regardless of whether the submitted email matches a verified reviewer. This prevents attackers from determining which emails are registered in the system. includes/api/class-researcher-handler.php
  • SECURITY
    OTP verification token — single-use + time-limited — The verification token issued after successful OTP verification is consumed immediately when unified_login() runs (deleted from the transient store). TTL is 3 minutes. This prevents replay attacks where an intercepted token could be reused. includes/api/class-researcher-handler.php
  • SECURITY
    Role verified server-side after wp_signon() — The role_hint field in the unified login form is a UX hint only. All role-based redirects are determined from the actual WordPress user roles returned by wp_signon(). A reviewer cannot gain researcher access by manipulating the form field. includes/api/class-researcher-handler.php
🔧 Compatibility
  • COMPAT
    PHP 7.4+ compatibility: spread operator removed from $wpdb->prepare() — Replaced the PHP 8.1 named-argument spread (...$args) with call_user_func_array([$wpdb, 'prepare'], ...). Plugin minimum is PHP 7.4 (declared in headers). includes/api/class-researcher-handler.php
  • COMPAT
    Theme-agnostic nav menu injection (4-strategy fallback) — The user menu widget injection supports: (1) replace existing login <li>, (2) append to primary nav <ul> (Astra, OceanWP, GeneratePress, etc.), (3) append to first <nav>, (4) fixed floating badge as last resort. assets/js/nav-user-menu.js
  • COMPAT
    Elementor & custom header builder support for login hiding — Client-side hideLoginItems() scans Elementor nav menu elements (.elementor-nav-menu li, .e-n-menu li) and standalone button widgets (.elementor-widget-button a) in addition to standard WordPress nav menus. assets/js/nav-user-menu.js
